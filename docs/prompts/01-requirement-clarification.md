# Prompt：需求澄清

**必须使用 Superpowers skill**：启动时加载 `using-superpowers`，然后调用 `brainstorming`。
`brainstorming` 的终止条件是调用 `writing-plans`——在需求文档通过门禁前不得提前触发。

读取需求草稿，在进入方案设计或编码前先完善需求。

只有当缺失信息会阻塞下一阶段时才提问。否则请做保守假设，并把假设记录到“风险和开放问题”。

检查：

- 业务目标
- 用户角色和业务场景
- 风险标签
- 范围内和范围外
- 业务规则
- 状态模型
- 权限和可信边界
- 验收场景
- 进入开发检查清单

输出：

- 不清楚或有风险的点
- 建议修改的需求文档内容
- 应启用的 review 类型和 skills
- 是否可以进入方案设计的 go / no-go 判断
